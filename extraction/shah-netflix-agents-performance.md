## Review notes

1. **This is the third corpus talk on agentic performance optimization, and the first from inside a large enterprise.** `walter-hud-agentic-perf-optimization.md` (batch 3, Hud — vendor) and `lopatecki-arize-signal-to-pr.md` (batch 12, Arize — vendor) describe the same loop shape; Netflix describes it as an internal platform practice with no product to sell. Convergences worth noting at review: all three ground the agent in production runtime data rather than the code base; all three require verification *before* a human is asked to look (Hud: re-run and verify impact; Arize: evidence attached; Netflix: tests + canary); and all three independently hit the human-attention constraint (Hud's "rain of 80 PRs" failure ↔ Netflix's noise-optimization section). **Divergence worth more:** Hud and Arize both stop at "the agent produces a well-evidenced cold start"; Netflix adds the persistence layer neither has — a catalog that makes run *n+1* cheaper than run *n*. If you seed only one of the three loop elements, `el-continuous-fix-loop` **[registry]** is the right survivor and this file's edges assume that.
