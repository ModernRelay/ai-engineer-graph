| `how-curate-post-training-data` | Stage it, ablate it, then prove the scaling curve | Decompose curation into stages (source → mix → filter → generate → filter) and settle each stage with an ablation rather than intuition; use LLMs to score question quality and hardness during filtering; **sample multiple answers per question instead of buying more questions** (16× on one question beat 16× the questions — the diversity of reasoning traces is what fine-tuning consumes); test teacher models empirically, because bigger is not reliably a better teacher; don't assume answer filtering, synthetic question rewriting or task augmentation help — all three underdelivered; publish/keep the recipe and validate it by showing metrics scale with dataset size before spending on scale; apply the identical method to agent trajectories and environments | `ReferencesElement → el-curation-recipe-ablation`, `el-curator`, `el-open-thoughts`, `el-open-thoughts-agents` |
| `how-post-train-for-compliance-and-latency` | Move rules out of the prompt and into the weights | When compliance is enforced by an ever-growing rule list in the prompt and latency is the casualty: collect the product's own logs, curate prompt/response pairs from them, **tag the spans that carry the required form** so the model learns structure rather than memorizing skewed values (imbalanced numerics are where post-fine-tune hallucination comes from), fine-tune, and measure compliance, latency and throughput together. Expect the ownership benefit to be part of the business case — the enterprise stops re-engineering prompts under each frontier release and stops paying frontier prices | `ReferencesElement → el-tag-guided-curation`, `el-curator` |
