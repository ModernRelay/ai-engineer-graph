| `ins-smallest-model-that-clears-the-task` | Edge engineering inverts the frontier question. You do not ask what the best model can do; you ask what the smallest model that clears this specific task is, because DRAM is the budget and weights, KV cache, runtime, render headroom and the operating system are all charged against it — and DRAM is getting more expensive, not less. | `how-size-a-model-for-the-edge` | Size the model to the device before anything else | Start from the four reasons to be on-device at all — latency (fast and consistent), privacy (data stays on the device), offline availability (the feature still works with no reception), and cost (cheap tokens multiplied by app-scale user interaction adds up quickly). ## Review notes

1. **`el-tiny-language-models` vs `el-small-language-models` [registry] — the merge decision.** The registry SLM brief already spans "millions to low billions", so on paper this talk could reuse it alone. I coined the tiny tier separately because this is the first artifact in the corpus to draw an **operational** line rather than a size range: 1–4B = prompting playbook, ~4 GB+ DRAM, laptop/high-end-phone/OS-bundled class; <1B = fine-tuning-or-fixed-task playbook, <2 GB, IoT/browser/consumer-robot class. Three signals and both insights hang off that distinction. If central reads them as one node, merge into `el-small-language-models`, widen its brief with the two playbooks, and rehome `sig-tiny-tier-flips-to-finetuning`, `sig-voice-to-function-calling-onboard` and `sig-local-models-displace-subscriptions`.
2. **`el-dynamic-quantization` [registry] reused across vendors.** The registry brief was written from Unsloth's selective per-layer scheme; Google's mixed 2/4/8-bit + per-layer-embedding work is the same concept independently implemented, and the corroboration is worth more than a duplicate node. If you prefer vendor-specific implementation nodes, split and cross-link — but note the registry already reuses concept-level elements across vendors elsewhere (`el-golden-dataset`, `el-judge-as-classifier`).
3. **Counter-edge on `pat-sovereign-ai` — justification and drop-option.** `sig-dram-cost-gates-edge-ai` carries `ContradictsPattern` because the corpus's local-first thesis has so far assumed the hardware trend runs in its favour, and the platform team that ships this stack says the opposite about the binding input: memory cost is rising (a 6 GB Raspberry Pi up ~2.5×), and phone makers are shipping *less* DRAM this year. `sig-edge-robot-interaction-gap` corroborates on the capability side (the cheap board's robot is visibly too slow for real-time interaction) but is left **pattern-less** rather than double-counting the counter-edge. **Drop-option:** if you read the DRAM material as *motivating* tiny models rather than contradicting local autonomy, flip it to `FormsPattern` or leave it pattern-less; the pattern then keeps only the Yaron survey counter-edge.
