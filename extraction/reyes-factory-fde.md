## Review notes

1. **Caption garbles.** "FTE" appears for **FDE**; "hardness" = **harness**; "pro- potential" = **potential**; "the hardness that we build" = "the harness that we build"; "verif- in a verifiable way" is a self-correction; "if we can hand over a model to you" = a *mental model / transformation model*, not an ML model. Numbers spoken loosely: "87% less likely to hit a bug" is offered as an illustrative example ("maybe 87%"), not a measured claim — treat as hypothetical, not evidence.
2. **`el-autonomy-ratio` figure ambiguity.** As spoken: "we ourselves have roughly 15 to 20% of what we call like autonomy, and our autonomy ratio is like in the upper 80%". The two numbers cannot both be the same metric. Most plausible reading: ~15–20% of work is fully autonomous, while within agent-run work ~80-something percent of actions are taken by AI before a human interrupts. Element brief records both as-spoken with the ambiguity flagged; verify before any public-facing use.
3. **`el-software-factory` vs `el-lights-off-software-factory` [registry]** (batch 11, Horthy). Deliberately coined as a separate node. Horthy's is a specific *configuration* — no human reads the code, review dropped entirely — which he argues fails. Reyes's is the *pipeline abstraction* (signal→deploy) with humans explicitly retained as the engineers of the system: "that does not mean humans are not part of engineering this system". Note the phrase collision: HumanLayer also markets itself as "building blocks for your software factory" and Reyes says Factory provides "a set of building blocks for building a software factory" — two vendors, same pitch, opposite positions on whether the code gets read. If you merge them at seeding, the Horthy/Mistele counter-edges to `pat-harness-over-model` would end up sharing a node with this file's supporting edge, which would be misleading. Recommend keeping both, optionally `el-lights-off-software-factory` `UsesElement → el-software-factory`.
4. **`el-agent-maturity-model` [registry] reuse is a widening.** Jones (batch 9) defined it as a capability ladder for agents; Reyes uses "autonomy maturity model" to mean an *organization's* roadmap to autonomous software development. Same name, adjacent-but-different referent. Reused rather than coining a near-synonym, per the reuse-aggressively rule — but if you would rather keep them separate, coin `el-autonomy-maturity-model` and drop this OnElement edge.
5. **Terminal-flicker cross-reference.** Reyes says Factory cannot verify terminal flicker in its own harness; Mistele/HumanLayer (batch 13) uses Claude Code's six-month terminal-flicker bug as evidence *against* loops-maxing. Same defect class, two vendors, opposite conclusions — worth a cross-file note at seeding, no edge proposed.
6. **`sig-fde-track-frontier-labs` is MC testimony, not Reyes's.** It is in this transcript because the intro was captured with the talk. If you prefer per-speaker provenance purity, drop it or re-attribute when the other four FDE-track transcripts arrive (it is the natural track-level signal).
7. **FDE-thesis proposal** (identical note in all four files of this set): *agentic products are customizable without limit, so implementation has moved from the buyer to the vendor; shipping software now means embedding engineers who co-build, measure and prove the outcome, which turns go-to-market into a delivery-and-product-feedback function.* Factory is the sharpest evidence for the "product-feedback" half — deployed engineers defined as the information stream from the biggest customers back into the product, with professional services refused precisely because it does not feed that loop.
