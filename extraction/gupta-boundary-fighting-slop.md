## Review notes

1. **⚑ "Slop" is defined incompatibly by two talks in this batch.** Gupta: **slop is any code you don't read** — a property of human attention. Branco/Taste Labs (`branco-taste-labs-ending-slop.md`): **slop is collapse to the mean** — a property of the output distribution. Neither entails the other. I coined `el-slop-as-unread-code` and `el-collapse-to-the-mean` as separate nodes rather than one polysemous `el-slop`; do not merge unless you want the ambiguity in the graph deliberately. The corpus-level observation worth keeping: two talks premiering the same week, both organized around ending slop, using the word for different phenomena — which is itself evidence that "slop" is doing rhetorical rather than technical work in the discourse.
2. **⚑ Product/company name resolution (highest-confidence-needed item in this file).** Captions say "BAML" once ("When we started building BAML"), then bare "ML" for every demo reference ("call the ML calculate function", "write a bunch of ML code", "ML has no function coloring"), and the sign-off is "I'm Vaibhav, and I work on **Bemo**". Resolution: the product is **BAML** and the company is **Boundary** — supported by (a) the single clean caption, (b) the in-talk gloss "what we might need is basically going to be a made-up language" (BAML = Basically A Made-up Language), and (c) the speaker metadata. Every bare "ML" in this file's briefs has been read as BAML. **Verify before public-facing use**; if wrong, `el-baml`, `co-boundary` and all six signals need renaming.
3. **Element count is high (9) — three are demote-to-prose candidates.** `el-design-doc-system`, `el-architecture-invariant-ci` and `el-zero-cost-execution-tracing` are single-company mechanisms and could be folded into `el-baml` / the KnowHows if you want fewer nodes. I kept them because each is a transferable practice stated as advice ("you two can go home and build these internal tools"), and because the design-doc one carries the batch's best negative result (the founder's own doc flood).
4. **`el-architecture-md` vs `el-agents-md` — merge decision needed.** Same motivation (model-agnostic repo guidance), different rules: AGENTS.md is the cross-vendor convention with architecture/constraints/dos-and-don'ts; architecture.md here is *invariants only*, deliberately tiny, and carries a human-escalation rule for the risky parts of the system. Options: (a) keep both and edge `el-architecture-md UsesElement → el-agents-md` (what I did), (b) merge into `el-agents-md` and keep Boundary's rules in signal prose. I lean (a) — the "only things that won't change for months or years" constraint is the actual content of the idea and it's absent from the AGENTS.md node.
5. **`pat-benchmark-trust-crisis` — mild COUNTER-flavoured evidence (NOT coined, per instructions).** Nothing here is about public benchmarks, but the A/B testing of language features on tool-call counts and error rates is a working example of **cheap, private, task-specific measurement that does its job** — because Boundary owns the whole loop (it generates the tasks, runs the agents, keeps the traces and defines the metric). That is the same shape as Feyzkhanov's private-benchmark argument and the same shape as batch-13's HumanLayer counter to `pat-durable-execution`: the failing thing is the *public, shared, third-party* instrument, not measurement as such. Worth recording in the candidate's ledger as a boundary condition on the claim.
6. **`pat-ai-native-org` candidate — moderate evidence (NOT coined).** An eight-person team abolishing code review, mandating parallel work, refusing tool standardization, and relocating human review to prose is an organizational-form claim, not just a tooling claim, and it comes with a stated productivity counterfactual (a programming language that "would have taken hundreds of thousands of man-hours"). Weaker than Block/Automattic/Machinecraft (small team, single company, no headcount or output numbers), stronger than the soft resonance points. `sig-boundary-ships-without-code-review` and `sig-writing-is-the-review-surface` are currently on `pat-value-of-judgement` and would rehome cleanly.
