| `el-alphalab` | AlphaLab | framework | training | Morgan Stanley's open-source agentic harness for automated quant research. Input is a path to a dataset (or an API spec) plus a natural-language description of what to predict; output is a suite of trained, containerized ML models. Three phases: **research** (~3–4 hours: builds and works a to-do list, sets up its Python environment, loads data, runs statistical tests, reads arXiv and technical blogs via web search, taking markdown notes per item that later agents query), **eval building** (see `el-eval-critic-loop`), and **mass experimentation** (see `el-strategist-worker-board`). Deliberately **not built on any off-the-shelf agent framework** — all custom code, itself largely written by Claude, for maximum freedom to tweak; functional tool calling keeps it provider-agnostic across OpenAI, Anthropic and open-source models. Three main tools: full shell access, web search, and a Slurm abstraction where the agent declares hardware ("4 H100s and this many CPUs") and submits a job rather than orchestrating anything. 1.0 released ~April 2026 with a ~40-page tech report and all code on GitHub |
| `el-strategist-worker-board` | Strategist/worker experiment board | concept | harness | AlphaLab's experimentation core, and its human-steering surface, formulated deliberately as a **Jira/Kanban board**. A *strategist* agent queries all context from earlier phases and keeps proposing experiments as cards in an "to implement" column; *worker* agents pull cards, write the implementation, write the Slurm config, submit to the cluster, wait for the job, inspect the training curves (underfit/overfit) and eval results, then write a **postmortem back to the strategist** — which is how the strategist self-evolves ("three transformer variants underperformed, XGBoost is working, explore more tree methods"). The board shape is what makes human steering natural: cancel cards, add your own, or chat with the strategist to push it toward a method. An ever-growing leaderboard ranks models against both the agent-visible eval and a **held-out private validation set**, with full lineage from idea to code |
| `el-eval-critic-loop` | Builder/critic eval construction | concept | harness | AlphaLab's answer to "if you optimize against a bad eval the whole thing falls apart". One agent builds the evaluation — writing all the code — and hands it to **two critic agents with different mandates**: one high-level, hunting conceptual errors and forward leakage of information; one programmatic, writing unit and integration tests against it. Findings return to the builder and the loop does not terminate until every critic is satisfied. Rationale stated: "LLMs aren't malicious, but they make very silly mistakes" |
| `el-environments-as-enterprise-moat` | Environments as the enterprise moat | concept | training | The talk's thesis and its 2.0 architecture. **"Evals and environments are the same thing — you just train in environments."** Fix a strict Kaggle-shaped boundary (data + description in, containerized model submissions out, public leaderboard score to the agent, private held-out score to the user), build on the order of **10–20 very careful environments**, and that becomes a reinforcement-learning signal rather than only a measurement. The proprietary data is one half of the moat; the other is **qualitative rubrics** derived from watching traces and asking "what makes a good researcher" — grading each rollout on adherence to the firm's research process, which is how human expertise gets encoded. Consequence he accepts explicitly: general auto-research becomes a **commodity** (GLM 5.2 is cited as already showing it), whatever sits in the middle is disposable, and the plan is to keep open-sourcing the harness because the environments hold all the value |

| `how-build-an-auto-research-harness` | Own the harness code; abstract the cluster, not the agent | Write your own harness rather than adopting an agent framework — in the Claude Code era you get max freedom to tweak anything, and the model writes most of it. Use functional tool calling so the whole thing stays provider-agnostic across frontier and open-source models. Give the agent three things: **full shell** (so it writes code, manages its own Python environment, runs things), **web search** (so it can read arXiv and technical blogs and reach the public state of the art), and a **cluster abstraction** where it declares hardware needs and submits a job instead of orchestrating hardware. ## Review notes

1. **Caption garbles.** **"GRPL" → GRPO** (the on-policy RL method; `el-on-policy-distillation` **[batch 5]** carries the adjacent concept and is the edge target). **"NeMo Tron" → NeMotron.** **"super cloud MD file" → "super CLAUDE.md file"** — the research phase is described as building a giant CLAUDE.md/`init` equivalent, which is a nice corroboration of `el-agents-md` **[batch 6]** but too glancing for an edge. **"Opus 4.5"** is stated cleanly and is a *dated capability claim*, so it matters: it is the model generation credited with crossing the long-horizon threshold in Dec 2025. **"self-recursive improvement"** is the speaker's phrasing throughout; `el-recursive-model-improvement` **[batch 5]** is the near neighbour but describes *model* self-improvement, so `el-meta-harness` was used instead.
2. **⚑ `pat-environments-economy` — the strongest *buy-side/enterprise* data point the candidate has.** Every prior data point is a vendor or lab (Harbor/Laude, Prime Intellect, Abundant AI, Snorkel, Andon Labs, Cai's analyst sizing). This is the first **non-vendor institution treating environments as its own strategic asset** — a bank open-sourcing its harness precisely because the environments are the moat, and encoding its quant expertise as grading rubrics rather than as code or prompts. It also independently restates the candidate's core identity claim in one sentence: *"to me evals and environments are the same thing — you just train in environments."* `sig-environments-are-the-enterprise-moat` is currently homed on `pat-model-not-bottleneck` and would **rehome on coin**. Note the tension with batch 13's SonderMind counter-instance (environments as public good, not asset class): Morgan Stanley open-sources the *harness* and keeps the *environments* — which is exactly the asset-class framing, not a counter.
3. **⚑ `pat-adaptive-harness` — a top-tier data point, and the first from a regulated institution.** "This itself is a verifiable loop — an LLM should be doing this meta-optimization" is as pure a statement of the candidate as the corpus has, and it is being run in production against models that go through a bank's risk process. Ranks with RELAI, DSPy Flex, AutoAgent and Uber's reflect/synthesize optimizer (batch 12). `sig-meta-harness-optimization-in-prod` is homed on `pat-harness-over-model` and would rehome on coin. **Note the awkwardness this creates:** the same talk that argues the harness should optimize itself also argues the harness is disposable and the environment is everything — if both `pat-adaptive-harness` and `pat-environments-economy` are coined, this file supplies evidence to both from a single thesis, which is worth a look when deciding whether those two candidates are really one claim.
4. **`pat-harness-over-model` — a support edge from an unusual direction.** The pattern has 8+ counter-edges. This talk supports it twice (the Dec-2025 threshold credits harnesses jointly with the model; the 2.0 architecture treats the harness as the optimizable object) while *simultaneously* declaring the harness commoditized relative to environments. That is not a contradiction — it is the pattern's own logic taken one level up (the scaffolding around the model matters; therefore optimize the scaffolding; therefore the scarce thing is the measurement that lets you) — but if you are weighing the pattern's health at review, count this as support **with a caveat**, not as a clean vote.
5. **`co-morgan-stanley` type.** `investor` is a poor fit for a full-service investment bank, chosen for consistency with `co-citadel` **[this batch]** and as the least-bad option. The registry already flagged `co-jpmorgan` **[batch 10]** as having no enum fit. **Recommendation: type all three the same way at seeding**, or add a `financial-institution` value to the Company enum — three nodes now justify it.
